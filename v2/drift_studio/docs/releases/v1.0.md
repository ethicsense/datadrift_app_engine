# drift_studio v1.0 릴리즈 노트 (2026-01-06)

## 개요

`drift_studio`는 멀티 모달리티 데이터셋에 대해 **EDA → Drift → Report(HTML/PDF)** 파이프라인을 **서버(UI 포함)**와 **CLI**에서 동일한 런타임으로 실행하는 것을 목표로 합니다.

## 포함 범위(What’s in)

- **서버**: FastAPI 기반 업로드/분석/리포트 제공 + Web UI(Vite/React)
- **CLI**: 로컬에서 동일 런타임으로 EDA/Drift/Report 실행
- **공통 런타임**: Plan 기반 실행, 산출물 표준화, 모달리티 auto 추론
- **리포트**: HTML 기본, PDF는 옵션(환경 의존)

## 포함하지 않음(What’s out)

- workspace(Git/DVC snapshot 등) 기능: **제거**
- 그래프 UI/Plan 시각화 도구: **미포함**

## 주요 기능

### 서버(API + UI)

- **FastAPI API 서버**
  - 데이터셋 업로드/관리, EDA/Drift 실행, 리포트 경로 반환 및 다운로드 제공
  - Plan/Runtime 기반 실행으로 라우터는 얇게 유지
- **Web UI (Vite/React)**
  - 데이터셋 업로드, 목록/상세, 분석(EDA/Drift) 결과 확인 및 리포트 다운로드 흐름 지원
> 참고: v1.0 이후 리팩터링에서 **비동기 작업/진행률/WS**는 단순화를 위해 제거되었습니다(필요 시 재도입 예정).

### API 엔드포인트(개념)

> 실제 상세는 `apps/api/app/routers/`를 기준으로 합니다. (아래는 “무엇을 할 수 있는지” 수준의 요약)

- **Datasets**
  - 업로드/목록/상세/삭제 등(데이터셋 관리)
- **EDA**
  - 결과 조회(캐시 우선, force 옵션으로 재실행)
  - zip 이미지 분석/클러스터링(일부 비동기)
  - task 상태 조회
- **Drift**
  - base/target 조합 drift 실행(캐시 우선)
  - 비동기 drift 실행 및 task 상태 조회
- **Report**
  - EDA 리포트 생성/경로 반환
  - 파일 다운로드
> 참고: WebSocket(`/ws/*`) 기반 진행률 스트림은 현재 제거되었습니다.

### 런타임(공통 실행기)

- **Plan + Runner**
  - `Ingest(입력 정규화) → EDA → Drift → Report`를 `Plan`으로 선언하고 `RuntimeRunner`가 실행
- **표준 산출물**
  - `artifact_index.json` + `artifacts/*` (아티팩트 인덱스/페이로드)
  - `report.html`, `report.pdf(옵션)`은 유지
- **모달리티 자동 추론**
  - `ddoc.yaml` 기반으로 모달리티를 자동 판정(`auto` 지원)
- **vendored ddoc 기반 실행(메인스트림)**
  - v1 `ddoc`를 `packages/ddoc`로 vendoring하여 동일 레포에서 설치/수정 가능
  - 실행은 `PythonExecutor`가 `ddoc` 플러그인(pluggy entrypoints)을 **직접 호출**하는 방식
  - 내장 EDA/Drift fallback 및 wrapper 기반 컴포넌트 계층은 제거됨

### 실행 흐름(동작 모델)

- **입력 정규화**
  - 입력이 `.zip`이면 out_dir 아래로 압축 해제 후 “압축 해제된 디렉토리”로 치환
  - 입력이 디렉토리면 `ddoc.yaml` 검증 후 그대로 사용
- **실행**
  - step 단위로 EDA/Drift/Report를 실행하고, 각 step 산출물을 표준 경로에 기록
  - 동일 산출물이 이미 존재하고 `force=false`이면 캐시로 재사용
- **리포트**
  - 가능한 경우 `driftstudio_reports`로 HTML/PDF 생성 시도
  - 환경/의존성 문제로 PDF 생성이 실패할 수 있으며, 이 경우 HTML/JSON 산출물은 유지될 수 있음

### 산출물 규격(파일)

- **Artifact Index**
  - `artifact_index.json`: run 단위 메타 + 아티팩트 목록
- **Artifact Payloads**
  - `artifacts/*`: 아티팩트 payload(큰 데이터는 ref로 분리)
- **Report**
  - `report.html`: 리포트 HTML
  - `report.pdf`: 리포트 PDF(옵션)

### CLI

- drift_studio는 별도 CLI 앱을 제공하지 않습니다.
- 대신 vendored `ddoc`는 CLI(`ddoc`)를 유지하며, 필요 기능(EDA/Drift 등)은 ddoc 플러그인 기반으로 수행됩니다.

### Docker

- `docker-compose.yml`로 `api + web` 기본 구동 지원
- 스토리지를 로컬 볼륨으로 마운트하여 산출물/데이터를 유지

#### Docker 실행 예시(개념)

- 서버: `docker-compose up` 또는 개별 실행으로 API/UI 구동
- 브라우저 UI: `apps/web`가 API를 호출하여 업로드/분석/리포트 다운로드

## 설치/실행 가이드(개념)

> 고객사 환경에 따라 설치 방법은 달라질 수 있습니다. 아래는 v1.0의 구성요소를 이해하기 위한 가이드입니다.

### Python(로컬)

- **루트 패키지 extras**
  - `drift-studio[api]`: API 구동에 필요한 의존성
  - `drift-studio[vision|text|audio|timeseries]`: 모달리티별 의존성(가벼운 기본 묶음)
  - `drift-studio[all]`: 개발/테스트 편의용 전체 묶음(무거울 수 있음)

### Docker

- compose는 `api + web`을 함께 띄우는 기본 구성을 제공합니다.
- 모달리티별 “선택 설치(vision/text/...)”를 Docker 빌드 단계에서 엄격히 분리하는 것은 v1.0에서 추가 정리가 필요한 영역입니다.

## 호환/제약 사항

- **데이터셋 업로드**
  - 현재 API 업로드는 `.zip` 형태 데이터셋을 전제로 하며, 내부에 `ddoc.yaml`이 필요합니다.
- **모달리티 플러그인**
  - v1 `ddoc`를 vendoring(`packages/ddoc`)하고, `PythonExecutor`가 pluggy entrypoints(`ddoc_text` 등)를 직접 호출합니다.
  - 플러그인이 미설치면 fallback 없이 **명확히 실패**합니다.
- **고객사별 배포 최적화**
  - 모달리티별 extras 선택 설치 전략은 루트 패키지에 정의되어 있으나,
    Docker 이미지 빌드에서 build-arg로 extras를 분기하는 구성은 추가 정리가 필요합니다.

## 알려진 동작/주의사항

- **`ddoc.yaml` 기반 검증**
  - 런타임은 입력 디렉토리에 `ddoc.yaml`이 없으면 오류로 처리할 수 있습니다.
- **Report(PDF)**
  - PDF는 WeasyPrint 런타임 의존성(cairo/pango/gdk-pixbuf 등)에 따라 생성이 실패할 수 있습니다.

## 파일/구성 참고

- API: `apps/api/app/`
- Web: `apps/web/`
- ddoc CLI(vendored): `packages/ddoc/` (엔트리포인트: `ddoc`)
- Runtime/Spec/Reports: `packages/driftstudio_{runtime,spec,reports}/`
- Modality plugins(vendored): `packages/ddoc/plugins/ddoc-plugin-{vision,text,audio,timeseries}/`
